# 2026-11-23

## Generic PDF wrapper / iframe routing

- IEEE `stamp.jsp` 是 HTML 外壳 + 全屏 `<iframe src=".../*.pdf?...">`。顶层 0 块 →
  `contentHelper.ts` 抛 `No translatable content found`；PDF 在 iframe 内，主 content script
  `all_frames=false`，且 iframe 里是 Chrome 原生 PDF viewer（非 PDF.js DOM），
  所以 `isPdfJsViewer()` 不会命中。
- 新增 `src/entrypoints/utils/pdfSource.ts`：`isPdfUrl()` + `findPdfSource()`，按 URL 形态
  （`.pdf` / `/pdf` / `/pdf/<id>` / `format=pdf`）、iframe/embed/object 属性与同源 child
  document 递归挖掘 PDF 源。无站点白名单。
- 接线：popup 翻译按钮先查当前 URL，再经 `relayToContent` 调 `findPdfSource`；命中则
  `tabs.update` 到 `pdf-reader.html?url=`。content script 在空页面错误时也挖掘并请求后台
  打开阅读器（覆盖快捷键/三击入口）。
- `pdf-reader/main.ts` 去掉 arXiv 硬限制；新增 background `fetchPdfBinary`（带 cookie、
  30MB 上限）把 PDF 字节交给 pdf.js，并用 `content-disposition` 文件名作标题。
- 测试：`src/__tests__/pdfSource.test.ts`（11 例）；全量 73 files / 708 passed；
  chrome + firefox build 通过；`vue-tsc --noEmit` 0 错误。
