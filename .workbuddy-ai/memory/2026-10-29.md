# 2026-10-29

## MappingValidator 假告警修复（句子计数）

**症状**：claude.com 文章页告警
`[MappingValidator] Block b41 suspect mapping: 句子数骤减：比 0.33 < 0.34 | origChars 113 transChars 43 | origSent 3 transSent 1`，
但译文正确、完整。

**根因**：原文是列表项
`Hard limits (validation, approval gates) and anything else that comes up mid-conversation (e.g. memory lookup) move into the tools.`
`countSentences` 按 `[.!?;。！？；]+` 切分，`e.g.` 的两个句点把 1 句拆成 3 句（`…(e` / `g` / ` memory lookup)…`），
中文译文 1 句 → 比值 0.333，刚好跌破 `minSentenceRatio 0.34`。字符比 0.38 正常，所以只有句子信号报警。

**修复**（`mappingValidator.ts`，两端各一份，逻辑一致）：
- `countSentences` 改为扫描式切分：`。！？!?` 恒为句末；`.` 仅在「后面不是词内字符
  （`3.5`/`node.js`）、不是已知缩写（`e.g./i.e./etc./vs./U.S./Mr.` …）、且后面首个实字符
  不是小写字母（`e.g. memory`、`wait... and`）」时算句末；`;`/`；` 不再算句末。
- 「句子数骤减」增加 `minOrigSentencesForCollapse`（默认 4）：3 句并 1 句是正常中文合并。

**为什么不用「整段字符比」兜底**：字符比在 en→zh 本来就有 2~3 倍密度差，靠它无法区分
「正常合并」和「拿到别的 block 的译文」。

**验证**：新增 `fanyi-extension/src/__tests__/mappingValidator.test.ts`（16 例）与
`vocal-saga/tests/mappingValidator.test.ts`（同 16 例，原 7 例 + 新增回归）。
extension 全量 67 files / 626 passed；vocal-saga 800 passed（5 个既有失败与本改动无关：
cacheKey provider/style、shorthand/translateUrl 默认语言、`/api/translate/url` 404、D1 source_lang）。
`tsc --noEmit` 两个文件均无报错（注意 `noUncheckedIndexedAccess`：用 `charAt(i)` 与
`match()?.[1]`，不要用 `str[i]`）。
