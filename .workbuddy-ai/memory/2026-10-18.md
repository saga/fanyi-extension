### 关键坑（以后拆这个文件会再遇到）

- **两个 composable 循环依赖**：`useContextGraph` 需要 `persistLiteraryMemoryToWorkspace`，
  `useLiteraryMemoryEditor` 需要 `contextGraphOverview`。解法：编辑器侧改成惰性 getter
  `getContextGraphOverview: () => contextGraphOverview.value`（闭包捕获绑定，调用时已初始化），
  调用顺序固定为 编辑器 → ContextGraph。
- **`const` 解构的 TDZ**：composable 调用位置必须晚于它引用的所有 `const`（`activeTab`、
  `effectiveDocumentTranslationMode`、`literaryMemory`）。函数声明会提升，`const` 不会。
- **区域切割要按函数边界**：`clearContextGraphPoll … handleAgentWorkspaceProjectUpdated` 之间
  夹着一个 prompt-sync `watch`，它属于 App 而非 ContextGraph，误切会丢 watch。
- `useContextGraph` 不再持有 `effectiveDocumentTranslationMode`（它是 dep），否则与 App 重复声明。
- 模板仍按原名称使用所有解构值；`vue-tsc` 的模板属性检查是唯一能发现漏暴露的地方。

## 跨项目：CodeBuddy Agent SDK 能力探针（与本仓库无关）

新建 `~/code-repos/codebuddy-sdk-probe/probe.mjs`（`node probe.mjs` 即跑，支持
`CODEBUDDY_SDK=` / `--sdk` 指定任意版本）。三层证据：解析 `lib/types.d.ts` 字段表 →
`tsc` 对象字面量（TS2353）→ 拦截 `child_process.spawn` 读真实 argv/env。

实测结论（0.3.274 / 0.3.276 / 0.3.282 一致）：
- `thinking`、`effort` **在 `SessionOptions` 里已声明且运行时已透传**（`--effort`、
  `--settings {"alwaysThinkingEnabled":…}`、`MAX_THINKING_TOKENS`）；
- `fallbackModel` 只在 `query()` 的 `Options` 里，`SessionOptions` 既没声明、`lib/session.js`
  也没塞进 transportOptions → **静默丢弃**；绕过用 `extraArgs: { 'fallback-model': 'x' }`；
- 0.2.3 里三个字段全无（`SessionOptions` 那时还是 `export type`），所以「文档说没有」对旧版成立。
