# 2026-10-24

## cube.dev 卡片内容不翻译 → `<aside>` 被整棵拒绝

**症状**：https://cube.dev/articles/what-is-a-semantic-layer 上，带底色的
"Key takeaways" 卡片 6 条要点全英文，紧随其后的段落正常翻译。

**根因**：站点用 `<aside class="KeyTakeaways_*">` 承载正文内要点框（另有
`ArticleCallout--tldr` / `--verdict` 两个）。`aside` 在 `SEMANTIC_SKIP_TAGS` 中
被 `FILTER_REJECT` 整棵拒绝 → 卡片内 `li` 全部丢失。实测抽取 50 块，修复后 61 块。

**修复**（两端同语义，各自实现）：
- 新增 `isContentAside(el)`（`blockExtractor/rules.ts`）：
  不在 nav/footer/dialog 内；class/id 不命中广告/推荐/分享/侧栏噪声；
  处于文章区域（article/main/role 或祖先 class 含 article/post/story/content，
  用 `hasContentTokens`，因为 CSS-module 类名 `Article_article__body__5ks9P`
  无法被 `ARTICLE_CONTAINER_CLASS_PATTERNS` 的 token 边界匹配命中）；
  且夹在正文流中（同级有 p/h2/ul）或文本 ≥200 字。
- walker 第 3 步：`tag === 'aside' && isContentAside(el)` → `FILTER_SKIP`
  （跳过自身、下钻），其余语义标签维持 `FILTER_REJECT`。
- 文件：`fanyi-extension/src/entrypoints/utils/blockExtractor/{rules,walker}.ts`、
  `vocal-saga/lib/translate/blockExtractor/{rules,walker}.ts`。
  这两份**不在** `check-sync` 字节级清单里（早已分叉），改动需手工对齐语义。

**测试**：两端各新增 `contentAside.test.ts`（6 例）：正文 aside 提取、
侧栏/related aside 仍拒、nav/footer 仍拒。

**验证**：extension 63 文件 597 通过（1 个 `prompt-style-switch` 失败为既有）；
server 791 通过（6 个既有失败：D1 mock 缺 `content_hash` 列、路由 404 期望、
prompt 文案，已用 `git checkout` 回退我的两文件复跑确认与本次改动无关）；
`wxt build` chrome+firefox 通过；server `tsc` / `tsc -p tsconfig.lib.json` 干净；
`check-sync` PASS。

**遗留**：`isContentAside` 依赖「同级有正文块」这一结构信号。真正的正文 aside
若被单独包在 `<div class="row">` 里且文本 <200 字，仍会被拒。
