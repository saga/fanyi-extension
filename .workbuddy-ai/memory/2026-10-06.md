# 2026-10-06

## 修复：服务端页缓存陈旧 → 译文错位（a16z.news「翻译内容和原文对不上」）

**现象**：`www.a16z.news/p/top-100-consumer-ai-apps-seventh`（Substack）上，
小节标题 `1. Three LLMs, three different games` 下面跟着的是**第 2 节段落的译文**
（"我们首次加入了基于观测到的消费者支出排名…"），后续每个 EN 段落也都显示**下一块**的
译文 —— 整体约 +10 个块的均匀错位。页面上没有任何报错。

**根因（三层）**：

1. 服务端缓存的双语 HTML 靠 `data-fanyi-block-id` 回填，而这些 id 只在**生成缓存那次
   抽取**里才有意义。页面一改（块插入/删除/重排），同一个 id 就指向另一个元素。
2. 服务端**早就实现了**陈旧校验（`/fanyi/page/check` 比对 `contentHash`，不一致返回
   **410**），但扩展端 `checkServerCache()` **从来没传过 `contentHash`** → 守卫是死代码，
   陈旧缓存无条件被返回并应用。
3. 扩展端唯一的校验是 `translatedText === block.text`（identity 检查），对「错位」零作用。

**证据（真实页面实测）**：当前抽取 **77 块**，服务端缓存 HTML **74 块**；缓存独有的尾部
`b69–b74` 是 Substack footer 装饰（`div`/`a`），当前页面对应位置是 `h4`/`button`；
当前独有的 `b75–b77`（`No posts` / `Ready for more?` / `Subscribe`）。截图里那份缓存则是
文章版本不同（第 1 节少约 10 个块）。同页还验证了「指纹刻意不看文本」：`b3` 是点赞数
`142 → 184` 的原地改文案，指纹**不应**因此失效。

**修复**：

- `computeBlocksFingerprint(blocks)` = `b1:h3|b2:p|…`（**id + tag，文档序**，不含文本），
  在 `/check`（query）与 `POST /fanyi/page`（body）都作为 `contentHash` 发出。
  `checkServerCache(config, blocks)` 的 `blocks` 已改成**必填**（编译期防止再次漏传 ——
  这个 bug 的本质就是「一个必需信息被写成了可选」）。
- `/check` 的 **410 当作未命中**（不是错误，不抛异常）。
- `applyServerTranslatedHtml` 回填前逐块校验服务端 `.fanyi-original` vs `block.text`，
  不匹配就**跳过该块**并计数，返回 `{ translatedIds, mismatched }`；`translateViaServer`
  返回同一形状。
- `translation.ts` 必须**先 `prepareDocument()` 再 `checkServerCache()`**（指纹需要
  `blocks`），且 `mismatched > 0` 时只记 warn，**不自动整页重译**（单个易变计数块就会让
  每次访问白跑一次 LLM；结构性漂移由指纹提前拦掉）。
- 文本比对是**单向包含** + 去空白重试 + 去 Cf 字符（兼容 HN `excludeFromTextSelectors`
  与 `collapseSpacedText`），不能用全文本集合相等（Chrome/Firefox 渲染差异会误报）。

**改动文件**：
- `src/entrypoints/content/serverTranslation.ts`
- `src/entrypoints/content/translation.ts`
- `src/__tests__/serverTranslation.test.ts`（适配新的返回形状 + 断言 POST 带 `contentHash`）
- `src/__tests__/serverCacheStaleMapping.test.ts`（**新增**，9 个用例）
- `vocal-saga/lib/app.ts`：`POST /fanyi/page` 改为**原样存客户端 `contentHash`**，仅在
  客户端没传时回退 `String(simpleHash(html))`。**绝不能从 `html` 重新推导** —— 指纹是
  字符串、simpleHash 是数字，两者永不相等，缓存会再也不命中。
- `vocal-saga/tests/appRoutes.test.ts`：新增 6 个用例（check 410/200/空 hash 204、
  POST 存客户端指纹、按指纹命中、无指纹回退 simpleHash、指纹不一致重译）。mock DB 加了
  `_lastInsertArgs` 便于断言写入的 `content_hash`。
