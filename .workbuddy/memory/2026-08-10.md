# 2026-08-10

## Netflix Tech Blog 翻译文字重叠根因与修复
**现象**：netflixtechblog.com 页面翻译后，中文译文显示在英文原文上方（重叠），而非正确的上下排列。

**根因（双路径问题）**：
1. **扩展端 CSS 被站点覆盖**：`styles.ts` 中 `.fanyi-original/.fanyi-translation` 仅用简单 class 选择器设 `display: block`，
   无 `!important`，Medium 等站点的全局 span 规则或 flex/grid 布局可覆盖导致重叠。
2. **服务端 `/force/` 路径完全不注入翻译 CSS**：`processTranslationHtml` pipeline 只有
   stripDangerousScripts → devirtualizeLayout → injectRedirectGuard，无 CSS 注入步骤。
   浏览器直访 `/force/` 时 `.fanyi-original/.fanyi-translation` 是裸 `<span>`（inline），定位完全由站点决定。

**修复**：
- **fanyi-extension `styles.ts`**：`.fanyi-original` 和 `.fanyi-translation` 加 `!important` + 防御性样式
  （position:static, float:none, clear:both, order:0/1）防止站点覆盖和 flex 反转。
- **vocal-saga `lib/app.ts`**：新增模块级 `injectTranslationCss(html)` + `TRANSLATION_CSS` 常量，
  插入 `processTranslationHtml` pipeline（strip → devirtualize → **injectCss** → redirectGuard）。
  智能注入点：`</head>` 前 > `<head>` 内 > `<body>` 后 > `<html>` 后 > 前缀兜底。
- 新增测试：`injectTranslationCss` 单测 ×6（覆盖各种 HTML 结构 + CSS 内容校验）。
- 全量测试：fanyi-extension 865 passed，vocal-saga **1123 passed**（+6）。
- 扩展已 rebuild，vocal-saga 已部署 CF Workers 版本 `54eac8df`。

## 翻译映射校验（mapping validation）规则——新增
- 用户提议：当原文与译文信息量（长短/句子数）明显不匹配时，应检查 mapping 关系（防 block id 错配）。
- 新增模块 `lib/translate/mappingValidator.ts`：纯函数 `countSentences(text)`（中英文通用句末切分）+
  `validateBlockMapping(original, translated, opts)` 返回 `{suspect, reasons, charRatio, sentenceRatio, ...}`。
- 信号设计（避免中文密度误报）：
  - 字符比用非对称区间：译文过长（>3.5x）始终查；译文过短（<0.2x）仅对较长原文（>40 字符）查，短文压缩属正常。
  - 更稳健信号是句子数：标题 1 句、正文多句；`maxSentenceRatio` 默认 2.5（1→3 句即告警），`minSentenceRatio` 0.34。
  - 需绝对字符差 >=25 才触发字符比判定，过滤微小波动。原文为空却有译文 → 直接标可疑。
- 接入点：`processTranslationWithCheck`（`lib/translate/translateApi.ts`）在 unchanged 检测循环内调用
  `validateBlockMapping`，可疑则 `console.warn('[TranslateApi] Block <id> suspect mapping: ...')` 并汇总
  `N/total blocks have suspect mapping`。覆盖 /fanyi/page、/translate/url-page、/force/ 全部路径。
- 行为：log-only 默认，不改翻译结果（避免误伤正常译文）；后续可加严格模式丢弃可疑译文回退原文。
- 测试：新增 `tests/mappingValidator.test.ts`（14 项）+ `tests/translateApi.test.ts` 集成用例 3 项
  （覆盖 mitsloan 式标题→正文告警、正常标题/正文不告警）。全量 1139 passed（原 1123 +16）。
- 已部署 CF Workers 版本 `a07c942c`，校验已在线上生效。

## fanyi-extension 也需要映射校验（用户追问后补上）
- 用户问"fanyi-extension 不需要修改么？"。结论：**需要**。原因：扩展有「本地降级翻译」路径
  （server 5xx/网络错误时降级到本地 DeepSeek，`translation.ts:296`），同样按 block id 配对译文、
  **不经过服务端**，服务端校验覆盖不到。而服务端回填与本地翻译最终都调用
  `applyBlockTranslation(node, translatedText)`（`utils/translationDisplay.ts`），该函数同时持有
  原文 `node.textContent` 与 `translatedText` → 是一次性覆盖两条路径的完美注入点。
- 移植校验逻辑到扩展：`src/entrypoints/utils/mappingValidator.ts`（与 vocal-saga 端算法/阈值一致，
  双仓各自自包含，避免跨仓依赖）。
- 在 `applyBlockTranslation` 内调用 `validateBlockMapping`，可疑则 `logger.warn('[MappingValidator] Block ... suspect mapping')`
  + 写 `node.dataset.fanyiMappingSuspect`。**log-only，不改展示**（与服务端一致）。
- 测试：`translationDisplay.test.ts` 新增 3 项（标题→正文告警+写 dataset、正常标题/正文不告警）。
  全量 **868 passed**（原 865 +3）。`npx wxt build` 成功（output/chrome-mv3）。
- 注：用户需在浏览器重新加载扩展才能生效；这不是"部署"而是本地重载。
