## 核查：thinking budget tokens 到底有没有用（2026-10-31）
追踪 `@tencent-ai/agent-sdk@0.3.276`（vocal-saga/local-agent-service）整条链路，结论：**数值对当前默认模型基本无效，只有"开/关"有效**。
- 链路：`codeBuddyThinkingOption()`（`src/agents/taskProfiles.ts:187`）→ `{type:'enabled',budgetTokens}` → SDK `lib/transport/process-transport.js:255-268` 写 env `MAX_THINKING_TOKENS` → CLI（`cli/dist/codebuddy-headless.js`，SDK 实际 spawn 的是 `dist/codebuddy-headless.js` 而非 bin）读到后写 `modelSettings.providerData.max_thinking_tokens`，并因 `budget>0` **顺带把思考打开**。
- 关键：chat-completions 组包时 `...providerData` 直接摊进请求体，所以数字会以非标准字段 `max_thinking_tokens` 出现在线上；但 `thinkingFormat:'deepseek'` 的翻译规则只写 `thinking:{type:'enabled'}`，**不碰数字**；整个 headless bundle 里 `budget_tokens` 出现 0 次（Anthropic 式预算根本没实现）。Responses API 路径在 `toResponsesModelSettings` 里**显式 omit 掉** `max_thinking_tokens`。
- 结论分级：① 只是开关的副作用（真）；② 数字进 body（真）；③ 对 `deepseek-v4.1-flash`（baseUrl opencode.ai/zen）影响思考长度（**基本无效**，DeepSeek 无此参数，网关是否认这个字段未验证）。
- **附带发现**：`deepseek-v4.1-flash` 的 `thinkingLevelMap={minimal:null,low:null,medium:null,high:'high',max:'max'}`，`getSupportedThinkingLevels` 把 null 视为不支持 → **低/中 effort 会被 clamp 成 high**，推理强度对默认模型也是个假旋钮。真正影响速度的只有思考开关。
- 因此：UI 删预算是对的；内部补 8192 无害但可删（`thinking.type='enabled'` + `alwaysThinkingEnabled=true` 已足够开启思考）。
- **已落档**：`docs/2026-10-31-thinking-budget-and-effort-analysis.md`（含链路图、请求体证据、复现命令、未验证事项），commit `cf40215` 已 push。

## 文档翻译提示词「输入语言：英语」修复（2026-10-31 夜）
- **现象**：文档翻译 prompt 里固定写着「输入语言：英语」。实测本机 6 个项目的 `prompt_revisions` 全是「英语」，其中项目 `8f9a86bd` 的 config 已经是 `sourceLang=fr`，但 system_prompt 仍写英语 —— 文本与配置已经错配。
- **根因链**：① `hydrateWorkspacePrompt` 把服务端存的 systemPrompt 快照当成 `documentSystemPromptOverride`（用户自定义 prompt），编辑器从此长期持有旧快照；② 同步 watcher 在改语言时把这份旧快照原样 POST 回项目（`workspacePromptInput` 直接读编辑器）；③ `resolveLanguageName(sourceLang, '英语')` 的兜底就是「英语」，空值时也会落成英语。
- **修法**（两仓）：
  - 扩展：`applyDocumentLanguageLines` 在 hydrate 时只重写「输入语言/目标语言」两行再 POST，**不重建整份提示词**（重建会把文风一起换成当前全局设置）；`workspacePromptInput` 无自定义时按设置重建，不再拿编辑器快照；同步 watcher 追加 `documentPromptStyle`（追加在数组末尾，前几项下标被 `graphContextChanged` 使用）。
  - 服务端：`languageMatch.ts` 新增 `documentLanguageName` / `applyRunLanguageDirection`，`translationAgent` 每次组装 systemPrompt 都按本次 Run 的语言重写两行（快照过期也不影响模型）；`auto` → 「自动检测（按原文实际语言判断，不要假定为英语）」，未知代码原样透传。
  - 文风随项目走：项目 Prompt config 新增 `promptStyle`（白名单校验），hydrate 回填 `readerConfig.documentPromptStyle`，设置页新增 `activePromptStyle` prop。
- **测试**：扩展 676 通过、两仓 `prompt-style-switch` 新增「auto 不得假定为英语」、本机服务新增 `tests/document-prompt-language.test.mjs`（6 项）、`tsc --noEmit` 通过。本机服务 321 项中 1 项 `document-agent-prompt.test.mjs` 的 reviewStrength 断言失败属预存问题（本轮未动 `normalizeDocumentTranslationStrategy`）。
