## 文档翻译「阅读」工具条对齐修复
- **现象**：用户截图反馈文档翻译页「阅读」Tab 顶部工具条（显示/审校/思考/自适应/翻译当前页/强制重译当前页）控件基线不齐、垂直错位。
- **根因**：`src/entrypoints/document/documentReaderStyles.css` 的 `.action-controls` 用了 `align-items: flex-end`（底部对齐），而 select/checkbox/button 高度不同；且 `.field.inline` 字体 `.8rem`、select 内边距 `.35rem` 与按钮（`.85rem`/`.4rem`）不一致。
- **修复**：`.action-controls` 改为 `align-items: center`、gap `.75rem`；`.field.inline` 统一 `font-size:.85rem`、gap `.4rem`；select 内边距 `.4rem .6rem` + 边框/圆角/行高；checkbox 设为 `1.05rem` + `accent-color:#0969da`。所有控件垂直居中且盒模型接近，与按钮等高对齐。
- **注意**：`.controls`（App.vue 263 行，竖向堆叠的设置块）仍保留 `flex-end`，不是本次截图问题，未改。
- **验证**：`wxt build`（chrome+firefox）重建；产物 `document-*.css` 中 `.action-controls` 已 `align-items:center`、`.field.inline` 新规则齐全。改完 UI 必须重建，否则浏览器加载的是旧构建（此前踩过 stale build 坑）。

## 思考选项简化（最终态：只有开/关）
- **确认语义**：三个值来自 CodeBuddy SDK `query()` 的 `thinking` 选项——`disabled`（显式关闭）、`adaptive`（开启，预算交给模型自适应，最多 32k）、`enabled + budgetTokens`（开启，固定 token 预算）。值不能改，只能改展示/取舍。
- **用户两次收紧要求**：先把「自适应/指定预算」改成说人话；随后明确**删掉「自动判断」和「思考量（tokens）」概念**，只保留开/关。
- **最终 UI**：只有两档——`不思考（最快）`（`disabled`）/ `思考（更慢，更稳）`（`enabled`）。设置页删除整个思考量（budgetTokens）选择器。
- **内部兼容**：旧 `adaptive` 配置在 UI 上映射为「思考」，不改写存储值；用户切换时才写 `disabled`/`enabled`。切到 `enabled` 时若 `thinkingBudgetTokens` 无效则补默认 `8192`（后端需要合法预算）。
- **同时清掉的术语**：`Thinking 模式`→`思考方式`，`Thinking Budget Tokens`→删除，`Effort（推理强度）`→`推理强度`，`Fallback Model（可选）`→`备用模型（可选）`，Low/Medium/High→低/中/高；轨迹页不再显示 thinking 预算数字。
- **测试**：`documentReaderComposableWiring.test.ts` 更新 effort 断言，并新增回归守卫（禁止 `value="adaptive"` / `自动判断` / `固定思考量` / `思考量（tokens` 重新出现）；21 个文档测试通过；重建产物新文案存在、旧概念 0 残留。

## 核查：thinking budget tokens 到底有没有用（2026-10-31）
追踪 `@tencent-ai/agent-sdk@0.3.276`（vocal-saga/local-agent-service）整条链路，结论：**数值对当前默认模型基本无效，只有"开/关"有效**。
- 链路：`codeBuddyThinkingOption()`（`src/agents/taskProfiles.ts:187`）→ `{type:'enabled',budgetTokens}` → SDK `lib/transport/process-transport.js:255-268` 写 env `MAX_THINKING_TOKENS` → CLI（`cli/dist/codebuddy-headless.js`，SDK 实际 spawn 的是 `dist/codebuddy-headless.js` 而非 bin）读到后写 `modelSettings.providerData.max_thinking_tokens`，并因 `budget>0` **顺带把思考打开**。
- 关键：chat-completions 组包时 `...providerData` 直接摊进请求体，所以数字会以非标准字段 `max_thinking_tokens` 出现在线上；但 `thinkingFormat:'deepseek'` 的翻译规则只写 `thinking:{type:'enabled'}`，**不碰数字**；整个 headless bundle 里 `budget_tokens` 出现 0 次（Anthropic 式预算根本没实现）。Responses API 路径在 `toResponsesModelSettings` 里**显式 omit 掉** `max_thinking_tokens`。
- 结论分级：① 只是开关的副作用（真）；② 数字进 body（真）；③ 对 `deepseek-v4.1-flash`（baseUrl opencode.ai/zen）影响思考长度（**基本无效**，DeepSeek 无此参数，网关是否认这个字段未验证）。
- **附带发现**：`deepseek-v4.1-flash` 的 `thinkingLevelMap={minimal:null,low:null,medium:null,high:'high',max:'max'}`，`getSupportedThinkingLevels` 把 null 视为不支持 → **低/中 effort 会被 clamp 成 high**，推理强度对默认模型也是个假旋钮。真正影响速度的只有思考开关。
- 因此：UI 删预算是对的；内部补 8192 无害但可删（`thinking.type='enabled'` + `alwaysThinkingEnabled=true` 已足够开启思考）。
