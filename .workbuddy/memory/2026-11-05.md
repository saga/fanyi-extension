# 2026-11-05

## 网页翻译日志诊断：CSS 快照降级 + content script fetch 被页面 CSP 拦掉

用户贴的日志：smithsonianmag `Stylesheet exceeds 512 KiB limit`、arxiv `unsupported @import condition: layer(ar5iv)`、末尾 `[ServerTranslation] network error: Failed to fetch`。

- **三条日志是两条独立链路**：CSS 快照 partial 只是显示层降级（保留原 `<link>`，服务端 Reader fallback 兜底），不会阻断翻译；让翻译失败的是最后的 `Failed to fetch`。不要把样式警告当失败根因。
- **512 KiB 硬上限误杀**：实测 smithsonianmag 主 CSS 607 KiB；background.ts 与 inlineStylesheets.ts 各自硬编码 `512*1024`。改为共享 `src/entrypoints/utils/cssSnapshotLimits.ts` 的 `MAX_CSS_SHEET_BYTES = 1.5 MiB`（与 maxBytesTotal 一致），两处不再漂移。总预算仍是 1.5 MiB，D1 行上限 2 MiB 不受影响。
- **@import layer(name) 不支持**：arxiv HTML 论文页主 CSS 仅 188 字节，全部内容靠两个 `layer()` import（实测 56.5KB + 22.8KB）。现在展开成 `@layer name{...}`，layer + media 组合保留；`supports()` 仍标记 partial（静态展开会改变特性检测语义）。
- **CSP 是 `Failed to fetch` 的根因之一，已实测而非假设**：Chromium 官方（Chrome 85+ content script 跨源 fetch 遵循页面 CORS/CSP）+ Playwright 实测 `connect-src 'self'` → `TypeError: Failed to fetch`。这类失败**服务端完全收不到请求，Worker 日志里没有记录**。smithsonianmag 的 CF 挑战页正是该 CSP。
  - 修法：新增 `proxyServerFetch` 消息 + background handler；`requestTranslationServer` 在直连抛错时改走 background 重试一次，成功则构造同契约响应；失败才抛 `ServerTranslationError`。`checkServerCache`(GET) 与 `translateViaServer`(POST) 共用。正常路径仍直连，避免整页翻译长请求依赖 MV3 service worker 保活。
  - 日志补齐 `url / bodyBytes / sentHtmlBytes / requestBytes`；用户可见错误改成白话并说明已尝试后台通道。
- **验证**：70 个测试文件 / 684 项全过；`vue-tsc` 无新增改动文件错误（预存的 `defineBackground`/`TranslationMode` 报错与本次无关）；Chrome + Firefox 已重建，产物含 `proxyServerFetch` 与新上限。
- 改动范围：fanyi-extension 代码；vocal-saga 仅在 `CROSS_PROJECT_SYNC.md` 记录「扩展端独有」，服务端无需改动。
