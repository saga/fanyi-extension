## 翻译只翻脚注的根因与修复（michaelnotebook.com/whichfuture）
- 现象：页面 69KB Pandoc 长文，正文段落直接挂在 `<body>` 下；Readability 多锚点正确映射到 `<BODY>`（anchors=4/5, mappingConf=0.80, contentCov=1.00），但 `detectArticleRoot` 无条件拒绝 body/html 回落评分，评分选中 `<section id="footnotes">`（score 1454），只抽到 25 块 / 8,792 字符，正文 115 块 / 52,786 字符完全没翻。
- 修复：`contentDetector.ts` 新增 `READABILITY_BODY_COMPLETENESS_MIN=0.8`。Readability 映射为 body/html 时，若 `articleTextLength / rootTextLen >= 0.8` 且 `mappingConfidence >= 0.8`，直接采用该根；否则仍回落评分。日志区分 consent 与 documentRoot 两种拒绝原因。consent 子树由 blockExtractor 的 noise 规则处理，不需要在 root 层加站点特例。
- 验证：该页面 root 从 `SECTION#footnotes` 变为 `BODY`，块数 25→115；`contentDetector.test.ts` 新增 body-root 用例；全量 789 测试通过，`vue-tsc` 通过，`npm run build` 通过。
- 提交：`4c05fdc`（含此前未提交的 package.json 版本号 0.84.0→0.85.0），已 push。扩展需重新加载才生效。
- vocal-saga 未改：其 `detectArticleRoot` 仅 density provider 使用且 `useReadability:false`，服务端页面翻译以客户端 blocks 为准。

## 两类残留问题也已处理（同日第三轮）
- Readability 解析失败：新增 `buildDomFallbackRoot`，用正式 walker 在 body 克隆上抽取的文本量作证据。评分根抽取量 < body 的 35% 且差 >2000 字符时改用 body。测试用 `vi.mock` 让 Readability.parse 返回 null，验证日志 `DOM evidence: scoring root <SECTION> yields 1360 chars vs body 5844 chars; using body`。
