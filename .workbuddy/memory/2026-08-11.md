# 2026-08-11 工作日志

## 修复 404media.co 正文未翻译（fanyi-extension）
- 现象：标题/图片说明翻译了，但正文 `<p>` 全部未翻译。
- 根因：`blockExtractor/walker.ts` 的 `shouldSkipByClass` 用后缀规则
  `token.endsWith('-' + pattern)` 匹配，导致 `<article class="post ... has-sidebar">`
  命中 `sidebar` 模式被整棵 REJECT。prepareDocument 从 `<main>` 起走，article 是子节点被
  评估并拒绝 → 正文子树全失。从 article 直接起走（article 是 walker root 不被评估）则正常，
  所以此前 walker-level 测试误报通过。
- 修复：`shouldSkipByClass/shouldSkipBySiteRules` 命中时，若 `tag==='article'||'main'`
  则改为 FILTER_SKIP（跳过自身、下钻子树），与已有 metadata 守卫的 article/main 特例一致。
  div/section 不豁免（否则 ad-content/sponsored-content 噪声 div 会被下钻提取）。
- 同步：`ARTICLE_SELECTORS` / `refineArticleRoot` 已含 `.post__content`（BEM 双下划线，Ghost 站点）。
- 验证：新增 contentHelper.test.ts 两个 404media 复现测试；全量 870 passed；`wxt build` 成功。
- 注：浏览器需重载扩展生效（本地改动，非线上部署）。

## 架构翻转：Readability 从兜底改为主条件（fanyi-extension）
- 用户要求：`detectArticleRoot` 不要用 Readability 兜底，改为「判断主条件」。
- 改动 `src/entrypoints/utils/contentDetector.ts`：
  - `detectArticleRoot` 现在**先跑 `tryReadabilityRoot`**，返回非 consent 且非 body/html 的根即采用（打保底分 SCORE_THRESHOLD+1）；
  - 仅当 Readability 返回 null / consent 容器 / body-html 时，才回落到手写评分算法；
  - 删除不再使用的 `isFragmentedArticleRoot`（碎片化由 Readability 自行聚合）；
  - body/html 兜底门：Readability 有时只能定位到 body（如 OneTrust 弹窗页真实文章是 body 直接子节点），
    此时转交评分取更精确容器，避免 walker 遍历整页误翻 GDPR 文本。
- 设计边界：Layer 0 站点规则 / Layer 1 显式 `ARTICLE_SELECTORS` 仍作为更高优先级快速通道
  （curated 精确，去掉会在已知站点 regression）；Readability 是 Layer 2 内的主条件。
- 验证：新增 `contentDetector.test.ts` 一个 404media 类结构测试（锁定 Readability 主条件契约）；
  旧 "Readability fallback" 测试改名/改注释为 primary；全量 871 passed；`wxt build` 成功。
- 注意：浏览器需重载扩展生效。
