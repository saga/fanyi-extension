# 2026-09-03

## DZone "假翻译" Bug：显示"页面已翻译"但实际无翻译

用户报 `dzone.com/articles/enterprise-architecture-in-ai` "说是页面已翻译，但是根本没有！"。

### 根因（非提取问题）
- **管线正常**：`prepareDocument` 返回 **139 blocks / 27K 字符**（正文完整在 blocks 29+）。
- 真正的 bug 在**翻译状态机短路**：
  1. 首次翻译：LLM 对 DZone 技术内容返回 **identity 翻译**（译文=原文）或服务端缓存了空结果
  2. `applyServerTranslatedHtml` 内部跳过所有块（`translatedText === block.text → continue`）
  3. 但 `translation.ts:289/329` **无条件设置** `body[data-fanyiTranslated='true']`
  4. 用户再点翻译 → `isPageTranslated()` 返回 true → `showStatus('页面已翻译') + return` → **什么都不做**
  5. 用户陷入死循环：每次点翻译都只看到"已翻译"，无法重新触发

### 修复（fanyi-extension）
- **两处守卫**（服务端路径 line ~288、本地路径 line ~338）：`translatedIds.size === 0` 时
  - 不设 `fanyiTranslated = 'true'`
  - 返回 `{ translated: false }`
  - 显示错误提示 `'翻译未生效（译文与原文相同），请重试'`
- **UX 改进**：`isPageTranslated()` 短路时的提示从 `'页面已翻译'` 改为
  `'页面已翻译（如需重新翻译请先恢复原文）'`，告知用户出路。
- 全套 **889 测试通过**。
- DZone 页面快照存入 `src/__tests__/fixtures/dzone-article.html`（220KB）供未来回归。

### DZone 页面特征（备忘）
- 无 `<main>`，1 个 `<article>`（offset 108528，在大量 script 之后）
- `<article><div class="content"><div class="header">...` 结构
- 139 块中前 28 块是噪声（面包屑/元数据/Likes/Comment/CTA），正文从 block 29 开始
- DZone 无现有站点规则；本次未加（根因不在提取侧）
