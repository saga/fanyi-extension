# 2026-08-04

## 修复：MIT Sloan 页面点击翻译后白屏

**现象**：访问 https://mitsloan.mit.edu/ideas-made-to-matter/... 点击翻译，整页立即变白。
console 最后一条日志是 `initiatePullPoptinsRequest()`。

**根因**：MIT Sloan 集成了 Poptins（poptins.com，营销弹窗工具）。Poptins 通过外部
CDN 脚本**运行时动态注入**全屏白色弹层，且恰好在点击翻译、正文翻译进行中才触发
（`initiatePullPoptinsRequest` 是注入入口）。扩展的 `hideBodyOverlays()` 只在翻译开始
时**同步跑一次**，此时弹层还不存在，所以没被捕获；动态注入的弹层既没被一次性隐藏，
也不在 `styles.ts` 的 `[class*="notification"]` 规则范围内（其 class 是 `poptin-*`
而非 `notification`），于是盖住整页 = 白屏。

**排除项**：`academics-overlay` 是独立 nav 浮层（不在 `<main id="main-content">` 内），
`hideBodyOverlays` 隐藏它是正确的，不是误伤正文；正文根 `<main role="main">` 识别正常。

**修复**（3 个文件 + 1 个测试）：
- `src/entrypoints/utils/blockExtractor/rules.ts`：`OVERLAY_PATTERNS` 增加 poptin
  识别（class/id 含 `poptin`，及 iframe src 含 `popt.in`）。
- `src/entrypoints/utils/contentHelper.ts`：`hideBodyOverlays` 候选选择器增加
  `[class*="poptin"]`/`[id*="poptin"]`/`iframe[src*="popt.in"]`；新增
  `createOverlayHider()`——翻译期间用 MutationObserver 持续隐藏"翻译开始后才注入"
  的动态弹层，先用廉价 CSS 候选选择器收窄再调 `isOverlayElement`，并跳过扩展自身
  UI（class 以 `fanyi-` 开头），不监听 attributes/characterData 避免性能与循环问题。
- `src/entrypoints/content/translation.ts`：`handleFullTranslation` 在 `prepareDocument`
  之后启动 overlayHider；控制器 `restore()` 时停止它。
- `src/__tests__/overlayHider.test.ts`：5 个用例验证 poptin/overlay 动态注入被隐藏、
  扩展 UI 与正文内 poptin 不被误隐藏、stop 后失效。

**注意**：`pnpm compile`(vue-tsc) 在本环境报大量**预存**错误（缺 WXT 生成全局类型
`defineContentScript`/`browser`、Vue 宏、compromise 类型、storage key 类型等），
与本次改动无关；本次改动的 3 个文件类型检查无报错。

## 跨项目澄清：vocal-saga 是否需要同样的修改
- vocal-saga 实为 `translation-api`（Netlify Functions 后端，linkedom/jsdom 解析
  静态 HTML），与 fanyi-extension 共用翻译核心逻辑（见 vocal-saga 的
  `CROSS_PROJECT_SYNC.md`：仅同步"翻译核心逻辑"，不覆盖浏览器特有入口）。
- **白屏/MutationObserver 修复（contentHelper.ts 的 `createOverlayHider`）——
  不需要、也不适用于 vocal-saga**：服务端不渲染页面、无运行时 DOM 注入、无白屏，
  MutationObserver 在服务端无意义。vocal-saga 用 `markGlobalNoise` + 
  `pipeline.ts` 里 `[data-fanyi-remove]{display:none}` 的 CSS 在抽取/产出阶段处理
  overlay，是另一套机制。
- **但 `blockExtractor/rules.ts` 的 `OVERLAY_PATTERNS` 增加 poptin 属于"站点规则"
  共享核心逻辑**：vocal-saga 的 `blockExtractor/walker.ts:241` 确实调用
  `isOverlayElement()`（基于 `OVERLAY_PATTERNS`）服务端跳过 overlay。其 notification/
  subscribers 规则已与 fanyi-extension 一致，仅缺 `poptin`。为保持一致可把 poptin
  补进 vocal-saga 的 `OVERLAY_PATTERNS`（classTokens/idTokens），但实际收益有限——
  Poptins 是客户端注入，服务端解析的静态 HTML 通常不含 poptin DOM。

## 第二轮：发现更深根因（Drupal 整页容器被当弹窗隐藏 → 白屏）

**机制**：Dialog 类整页容器（如 Drupal 的 `.dialog-off-canvas-main-canvas`）类名含
`dialog`/`overlay`，被 `isOverlayElement` 判为弹窗。旧 `hideBodyOverlays`/`createOverlayHider`
只跳过 `articleRoot` 的**后代**与 `body/html`，但**未跳过祖先**。当该容器是 `<main>` 的
**祖先**时，会被标记 `data-fanyi-remove`，而扩展注入的 `[data-fanyi-remove]{display:none}`
会把整个页面容器（连同正文）一起隐藏 → 整页白屏。

**两页机制不同**：
- **sunxiunan（vocal-saga 服务端输出）**：原始已下发 HTML 自带 `data-fanyi-remove="true"`
  在 `dialog-off-canvas-main-canvas`（`<main>` 祖先）上，且内联 `[data-fanyi-remove]
  {display:none}` CSS（实测 31 处，1 处为祖先）→ 即使不开扩展也白屏。根因在 vocal-saga
  的 `markGlobalNoise`/抽取误标 + `pipeline.ts` 序列化进产物。**修复在 vocal-saga 服务端**。
- **mitsloan（纯扩展路径）**：原始 HTML 无 `data-fanyi-remove`，是 Poptins 动态注入浮层
  的纯扩展场景（首轮 `createOverlayHider` 已覆盖）。

**本轮修复**：
- fanyi-extension `src/entrypoints/utils/contentHelper.ts`：
  - `hideBodyOverlays` 增加 `if (el.contains(articleRoot)) continue;`（跳过正文根祖先）。
  - `createOverlayHider(articleRoot?)` 新增祖先保护 `if (articleRoot && el !== articleRoot
    && el.contains(articleRoot)) return;`。
  - `src/entrypoints/content/translation.ts`：`handleFullTranslation` 计算 `articleRoot`
    （`document.querySelector('main, article, [role="main"]')`）并传给 `createOverlayHider`。
- vocal-saga `lib/translate/pipeline.ts`：新增 `stripRemoveMarkersFromAncestors(doc)`，在
  输出序列化前剥离 `<main>` 祖先上的 `data-fanyi-remove`（真正的浮层/广告平级保留隐藏）。

**验证**：
- vocal-saga 服务端修复：用 linkedom 对真实 `sun476.html` 跑 `stripRemoveMarkersFromAncestors`
  → 祖先 wrapper 去标记（31→30 残留，30 个为正当浮层），PASS。vocal-saga `tsc --noEmit` 干净。
- 扩展修复：`src/__tests__/overlayAncestorFix.test.ts`（2 用例）经真实 `prepareDocument` 验证
  祖先容器/`main` 不被标记、poptin/cookie 浮层仍被标记且正常抽取块；`createOverlayHider`
  启动不标祖先、动态注入 poptin 被 MutationObserver 捕获。扩展全量 vitest 861 用例全过。
- **Playwright 实时调试受阻**：headless Chrome-for-Testing（`--headless=new` + `--load-extension`）
  下 unpacked MV3 的 content script 不执行（无扩展样式注入、`window.chrome.runtime` 为
  undefined、Alt+T 无响应），故无法在 Playwright 里实跑翻译。已改用确定性 vitest 验证（更强）。
  备注：`FloatingBall.vue` 是死代码，桌面端翻译由 popup / `Alt+T` 快捷键 / 右键菜单触发，
  并非自动悬浮球——之前 debug 脚本等待 `.floating-ball` 是错误假设。
- **CORS 报错**（`mitsloan.mit.edu/manifest.json?_format=json` 被 s.sunxiunan.com 拦截）
  是博客链接预览组件抓 Drupal 文章 manifest 的页面噪声，与白屏无关，忽略。

**待办**：sunxiunan 公网页需 redeploy vocal-saga（含 pipeline 修复）后才会停止白屏；
扩展已 build（`output/chrome-mv3`）可在 Chrome 加载验证。
