## 线上站点诊断：info.deeplearning.ai（The Batch 邮件归档页）翻译不全

用户报「提示已翻译，但只有极少部分段落翻译」。用真实页面 HTML + jsdom 跑真实
`detectArticleRoot` + `extractBlocks`（临时 vitest 探针，已删除）复现并定位三层根因。

页面特征：HubSpot 邮件简报（`body#hs_body`、table 布局、**无 article/main/section**）。
正文被 HubSpot 拆成多个兄弟 `div#hs_cos_wrapper_hs_email_body_old{N}` module，
真正的完整正文容器是 `div#hs_cos_wrapper_main`（33621 字符 / 116 blocks）。

### 实测数据
| 项 | 值 |
|---|---|
| Readability 正文 | 27,499 字符 / 85 段 |
| mapper 锚点（5 个）合计 | 1,144 字符 |
| contentCoverage | 0.042（阈值 0.3）→ **返回 null** |
| 兜底评分选中 | `div#hs_cos_wrapper_hs_email_body_old3_`（3820 字符） |
| 实际提取 | **9 blocks / 3,793 字符** |
| 应有（阈值压到 0.001 后） | LCA=`div#column_0_0`，**116 blocks / 32,331 字符** |
| 评分对比 | old3_（0 链接）16989.6 vs main（40 链接）6343.3 |
| extractBlocks(body) | **0 blocks**（table 层被 REJECT） |

### 三层根因
1. **主因 · `readabilityRootMapper.ts` 的 contentCoverage 指标定义错误**：
   分子 = 命中的 maxAnchors(5) 个锚段落 textContent 之和，分母 = Readability 全文。
   → 覆盖率 ≈ 5×段长/全文，与文章长度成反比。本例 0.042。
   → **数学后果：正文超过约 5,000 字符时 Readability 主条件 100% 失效**，静默退回评分。
2. **`scoreElement` 结构性偏差**：基础分 `textLength/(linkCount+1)×log(textLength)` +
   大容器惩罚 → 奖励「无链接纯文本片段」，惩罚「含导航链接的完整正文容器」。
   本例选中只含 9 段的 old3_。
3. **`table/tbody/tr/td/th` 在 `SKIP_SET`（整棵拒绝）**：对 table-layout 站点
   （HubSpot / Mailchimp / Substack 归档）致命。实测 `div.hse-body-background →
   table → tbody → tr` 全 0 块，只有 root 落到 `td` 或更深的 div 才恢复 116 块。
   → body-fallback 路径对这类站点彻底失效。

### 修复方向（待用户确认，尚未改动任何代码）
- P0：重定义 contentCoverage 为「段落命中率」而非「字符长度比」；用已有的 `coverage`
  （rootTextLen/articleTextLength）做二次校验防止 LCA 过窄/过宽；maxAnchors 随文长自适应。
- P1：锚点质量过滤（实测 anchor[4] 是页脚 boilerplate「Thoughts, suggestions, feedback?」
  ，但它反而帮 LCA 扩到了正确范围，不宜简单丢弃）。
- P2：兜底评分对 linkDensity 做上限 clamp，改用 `<p>` 文本量而非整体 linkCount。
- P3：区分「数据表」与「布局表」，布局表降级为 FILTER_SKIP 继续下钻。

探针页面存于 `/tmp/dom-probe/page.html`（82KB，未入库，需要时可重建）。

## 已修复：Gartner 新闻稿页 "No translatable content found"

用户报 `gartner.com/en/newsroom/press-releases/...` 翻译报 "no translation content found"。
用 Playwright MCP 真实浏览器绕过 Cloudflare 抓到完整 DOM（9 个 `<article class="article-text">`
兄弟碎片 + 共同祖先 `div.aem-Grid` 含 h1）。

### 诊断结论
- 在**渲染后** DOM 上 `prepareDocument(document)` 返回 **103 blocks**，根选 `div.aem-Grid`
  （score 77.6，含 h1 + 全部 9 碎片）。管线逻辑本身**无 bug**。
- headless Chrome 被 Cloudflare 403 拦截，本地无法 100% 复现用户 0 块，疑为旧构建 /
  Firefox AEM 渲染时机差异。→ 加确定性站点规则兜底。

### 修复（fanyi-extension）
- 新增 `src/rules/gartner-rules.ts`：`hostPattern:'*.gartner.com'` +
  `articleRootSelector:'[class*="aem-Grid"]'`。用属性选择器而非 `div.aem-Grid`：
  jsdom 在 innerHTML 替换后 class 选择器有缓存缺陷（`div.aem-Grid`/`.article-text` 均返 NULL），
  而 `[class*="aem-Grid"]` 稳定解析且文档顺序首个即包裹整篇的顶层网格。
- 注册进 `src/rules/index.ts` 的 `RULES`。
- 回归测试 `src/__tests__/gartner.test.ts`（4 用例，文件头 `// @ts-nocheck` 因未装 @types/node）
  + 真实页面快照 `src/__tests__/fixtures/gartner-press-release.html`（350KB，从
  `.playwright-mcp/full-page.html` 移入）。
- 全套 888 测试通过，tsc 对改动文件无报错。
